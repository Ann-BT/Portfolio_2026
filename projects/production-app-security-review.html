Production Web Application Security Review & Remediation Guidance

A self-directed, comprehensive security review of a confidential production web application providing automated document processing and Large Language Model (LLM) translation workflows.

Conducted black-box, grey-box testing, and source code auditing across frontend, backend microservices, and container infrastructure. Reported high-severity vulnerabilities with remediation guidance to backend engineers, while directly authoring and implementing frontend security hardening.

1. Critical Vulnerabilities Identified & Remediated

Vulnerability VectorSeverityTechnical ImpactRemediation Delivered
Broken Access Control (IDOR)HighInsecure direct object references allowed unauthorized cross-tenant document fetching at the database query layer.Enforced session-bound ownership validation at database query layers.
Mass AssignmentMediumUnrestricted request body payloads allowed parameter tampering during model profile creation.Replaced loose dict unpacking with strict Pydantic schema validation.
File-Processing Flaws (XXE, Zip Slip, Zip Bomb)HighParsing untrusted XML documents exposed server file retrieval (XXE); archives threatened filesystem overwrite (Zip Slip) and decompression DoS bombs.Migrated parser to defusedxml, implemented magic-byte file header verification, archive path normalization, and dynamic extraction timeouts.
Server-Side Request Forgery (SSRF)HighONLYOFFICE document server integration accepted arbitrary webhook callbacks, allowing internal cloud network probing.Enforced HMAC-signed JWT authentication tokens and internal IP allowlisting.
Infrastructure & Deserialization RisksCriticalExposed internal ports (Database, Redis, vLLM inference engine); Celery task worker configured with unsafe Python pickle deserialization (potential RCE); prompt injection vectors in LLM translation prompts.Isolated backend containers onto internal Docker bridge networks; migrated Celery serializer to JSON; implemented prompt-delimiter guardrails and output sanitization.

2. Direct Frontend Security Implementation

Beyond reporting backend findings, directly authored and deployed defensive layers across the client application:

  • Cookie Security: Enforced HttpOnly, Secure, and SameSite=Strict cookie flags to prevent script-accessible session tokens.
  • Content Security Policy (CSP): Implemented strict CSP headers restricting script and connect origins, mitigating XSS blast radius.
  • Client Route Guards & Storage Hygiene: Added cryptographic session expiry listeners and automated memory/cache cleanup on logout to completely eliminate XSS-driven session persistence.
  • Compliance: Supported compliance verification for a Level 3 Information System Security accreditation standard.
